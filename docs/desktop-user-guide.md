# HarnessKit Desktop 사용자 가이드

`v0.1.0-beta.6`의 한국어 사용 안내입니다. 앱 다운로드·체크섬 확인·macOS 첫 실행 보안 승인은 [README 설치 안내](../README.md#installation-guide)를 따라주세요. 이 가이드는 앱을 연 뒤의 작업을 설명합니다.

> 처음 적용할 때는 테스트 프로젝트나 복사본을 사용하세요. 실제 파일을 설치·제거하기 전에는 사용자가 직접 백업해야 합니다. 설치 전체의 자동 백업·자동 rollback이나 도구 runtime 성공을 보장하는 앱은 아닙니다.

## 빠르게 시작하기

| 화면 | 확인할 내용 | 저장소 연결 |
| --- | --- | --- |
| **Harness Components** | HarnessKit 원본 구성, 컴포넌트·Profile·Workflow 관계, 설치 계획 | 필요 |
| **PC 설치 하네스** | Mac과 발견된 프로젝트의 도구 파일, 원문, 스캔 상태 | 조회·검색·제거에는 불필요; 가져오기에는 필요 |

1. 원본 구성을 보려면 HarnessKit Git checkout을 연결합니다.
2. **Harness Components**에서 컴포넌트를 선택하고 오른쪽 상세를 읽습니다.
3. 설치가 필요할 때만 **Install action**에서 **Install preview**를 만들고, 변경 내용을 승인한 뒤 적용합니다.
4. **PC 설치 하네스**에서 로컬 파일을 검색하고 전체 원문을 확인합니다. 가져오기·제거·AI 설명은 각각 별도 동작입니다.

## 1. HarnessKit 폴더 연결과 새로고침

**SoT(Source of truth)**는 컴포넌트의 기준 정의가 있는 HarnessKit 저장소입니다. 앱 설치 폴더나 설치 대상 프로젝트와는 다릅니다.

- 상단 **로컬 checkout 경로**에 Git checkout 폴더의 **절대 경로**를 입력하고 폴더 아이콘 **HarnessKit 폴더 연결**을 누릅니다. `components/registry.yml`이 있는 HarnessKit 저장소를 선택하세요. DMG나 `HarnessKit.app` 경로를 넣지 않습니다.
- 폴더 선택기를 쓰려면 입력란을 비우고 폴더 아이콘을 누르거나, 연결 전 화면의 **기존 HarnessKit 폴더 선택**을 누릅니다. 입력란의 `~` 예시 대신 폴더 선택기나 절대 경로를 사용하는 것이 안전합니다.
- **HarnessKit 저장소 내려받기**는 공개 저장소를 앱 전용 폴더에 clone해 연결합니다. Git과 네트워크가 필요하며, **beta.6 태그를 자동 선택하는 기능은 아닙니다**. 같은 버전의 원본이 필요하면 README의 beta.6 checkout 연결 절차를 사용하세요.
- 연결 후 컴포넌트 수와 **Repository state**의 Branch·Working tree·Recent commits를 확인합니다. 화면의 수는 연결한 checkout 기준이므로 가져온 컴포넌트나 저장소 버전에 따라 달라질 수 있습니다.

탭 옆 새로고침 아이콘은 **현재 대시보드**에만 적용됩니다. **Harness Components 새로고침**은 로컬 저장소를 다시 읽고, **PC 설치 하네스 새로고침**은 Local scan을 다시 시작합니다. 저장소의 `git pull`이나 앱 업데이트를 대신하지 않습니다. 연결·읽기·스캔 진행 중에는 해당 새로고침이 비활성화됩니다.

## 2. 컴포넌트, 관계와 의존성 살펴보기

- 왼쪽 **Component filter**에 이름, Canonical ID, kind, domain을 입력합니다. `components`와 `profiles`를 펼쳐 항목을 선택할 수 있습니다. 이 필터는 왼쪽 트리 검색이며 전체 원문 검색은 아닙니다.
- 가운데 **Component Map**에서 구성 관계를 살펴보고, **Fit**·확대·축소로 시야를 조절합니다. **그래프 접기**로 작업 공간을 확보할 수 있습니다.
- **매트릭스 펼치기**를 누르면 **Profile Matrix**가 나타납니다. Profile은 구성 묶음이며, 선택하면 해당 멤버가 표시됩니다. **Unprofiled**는 현재 Profile에 포함되지 않은 컴포넌트 묶음입니다.
- 컴포넌트를 선택하면 오른쪽 **Component detail**에 설명과 **관련 Workflow**, **관련 Profile**, **관련 Component**가 표시됩니다. **기술 정보**를 펼쳐 Targets의 상태, Owned files, Canonical ID, **Relation evidence**를 확인하세요.
- 의존성·재사용을 포함한 관계는 **선언된 구성 정보**입니다. 관계가 보인다고 도구가 이를 실행했거나 의존 항목을 모두 자동 설치한다는 뜻은 아닙니다. 실제 설치 범위는 Preview의 **Components**와 **Planned artifacts**로 확인합니다.
- Workflow를 선택하면 정의된 단계와 **정의 상태**의 Authored·Runtime을 볼 수 있습니다. 단계 순서는 실행 이력이 아닙니다. **Component Dev Guide**도 저장소에 정의된 제작 절차를 보여주는 안내이며 자동 제작·실행 버튼이 아닙니다.

## 3. 설치: Preview → 승인 → Apply / Verify

### 대상 설정과 미리보기

1. 컴포넌트를 선택하고 오른쪽 **Install action**으로 이동합니다.
2. **Profile**, **Target tool**, **Scope**, **Target root**를 확인합니다. Profile을 적용하면 선택한 컴포넌트 하나가 아니라 해당 Scope의 Profile 구성 묶음이 대상이 될 수 있습니다.
3. 일반 프로젝트 적용의 **Target root**에는 미리 만든 대상 폴더의 절대 경로를 넣습니다. SoT checkout을 대상 프로젝트로 착각하지 마세요. 존재하지 않거나 심볼릭 링크를 거치는 경로는 거부될 수 있습니다.
4. **Install preview**를 누릅니다. 아직 대상 파일은 바뀌지 않습니다.
5. **적용 위치**, **Components**, **Planned artifacts**의 destination, **Skipped writes**, **Warnings**, **Runtime gates**, **Required approvals**를 검토합니다. 건너뛴 파일이나 지원 범위 오류를 성공으로 해석하지 마세요.

**Scope의 `User`/`Project`와 Target 선택지가 보인다는 사실만으로 모든 조합이 지원되지는 않습니다.** 컴포넌트·Profile·대상별 계약에 따라 Preview가 거부될 수 있습니다. 예를 들어 Target `project`는 `Project` Scope를 사용하며, 프로젝트 전용 규칙을 User 전체에 적용하는 경로는 아닙니다. 기본 컴포넌트에는 해당 Profile을 사용하고, `component:…` 개별 적용은 가져온 컴포넌트의 검증된 출처 연결을 위한 경로입니다.

첫 연습은 **Harness Maintenance Project Context**를 선택해 Profile `harnesskit.profile.harness-maintenance`, Target tool `project`, Scope `Project`로 Preview를 만들어보세요. 비어 있는 테스트 폴더를 대상으로 하며, `AGENTS.md`·`CLAUDE.md`의 예정 변경을 확인한 뒤에만 적용합니다.

### 명시적으로 승인하고 결과 확인하기

1. **이번 적용 승인**의 대상·파일 변경 확인란을 체크합니다.
2. Preview가 추가로 요구한 경우에만 관리 전환, 외부 수정 검토 후 교체, 기존 destination overwrite, runtime gate 승인도 확인합니다. 외부 수정은 표시된 차이를 검토하고 유지 또는 교체를 선택하세요.
3. **승인한 preview 적용**을 누릅니다. 적용하지 않으려면 **이번 적용 취소 · 파일 변경 안 함**을 선택합니다. 관리 중인 원본의 외부 수정을 유지하려면 **도구 쪽 변경 유지 · 이번 적용 취소**를 사용합니다.
4. 결과의 **Destination outcomes**에서 파일별 `apply`·`verify`와 오류를 확인합니다.

| 결과 제목 | 의미 |
| --- | --- |
| **Install verified** | Apply와 파일 readback 검증이 통과했다는 결과. 도구가 파일을 읽고 실행했다는 runtime 증명은 아님 |
| **Apply / verify partial** | 일부 destination만 반영됐거나 검증되지 않음. 각 파일을 확인해야 함 |
| **Install failed** | 적용 실패 또는 유효한 성공 근거 없음. 대상의 실제 상태부터 확인해야 함 |

입력이나 선택을 바꾸거나 SoT를 새로 읽으면 기존 Preview·승인이 폐기됩니다. 원본 변경으로 계획이 오래됐거나 한 번 적용한 뒤 재시도할 때도 **다시 Preview → 다시 승인**하세요.

**Apply 전체는 원자적이지 않고 자동 rollback이 없습니다.** 실패하거나 응답을 받지 못해도 일부 파일은 바뀐 채 남을 수 있습니다. 자동으로 원상 복구됐다고 가정하지 말고 destination별 결과와 실제 파일을 확인하세요. 필요하면 직접 준비한 백업으로 복구한 뒤 새 Preview를 만듭니다. Runtime gate 승인도 실제 hook 실행 성공을 검증하지는 않습니다.

## 4. PC 설치 하네스: 스캔과 검색

이 화면은 SoT 연결 없이 사용할 수 있습니다. 처음 진입해 사용할 스냅샷이 없으면 자동으로 스캔을 시작합니다. 이후 변경 사항은 새로고침으로 다시 확인하세요.

### 찾고 읽기

- 왼쪽 **전체 위치**, **User**, **Project 전체** 또는 발견된 프로젝트를 선택합니다. **프로젝트 이름 검색**은 프로젝트 **이름만** 검색하며 경로는 검색하지 않습니다.
- 가운데 도구 필터와 **All kinds**/종류 필터를 사용합니다. 도구 목록에는 Claude Code, Codex, Antigravity IDE·CLI, Hermes 등의 관찰 가능한 항목이 표시될 수 있지만, 모든 설치·가져오기 기능을 지원한다는 뜻은 아닙니다.
- **설치된 하네스 검색**은 이름·설명·safe locator를 검색합니다. 전체 원문 내용은 검색하지 않습니다. 결과가 없으면 **필터 해제**를 사용하고, 결과가 많으면 **이전**·**다음**으로 이동합니다.
- 항목을 선택하면 오른쪽 **하네스 상세**에 경로와 상태, **전체 원문**이 나타납니다. 긴 원문은 이전·다음 또는 **원문 위치** 슬라이더로 읽습니다. **스캔 후 변경됨**은 스캔 시점 이후 원본이 달라졌다는 뜻입니다.
- **Finder에서 보기**와 **경로 복사**는 위치 확인용입니다. 원문 조회·스캔·검색은 도구 원본 파일을 수정하거나 그 안의 명령을 실행하지 않습니다.

특정 프로젝트의 **스캔 제외 규칙 편집**은 읽기 전용 조회와 다릅니다. **저장하고 다시 스캔**은 해당 프로젝트의 `.harnesskitignore` 텍스트를 실제 저장하고 전체 Local scan을 다시 요청합니다. 하네스를 삭제하는 기능은 아닙니다.

### 스캔 결과를 해석할 때

- 스캔은 도구별로 정해진 파일과 발견된 프로젝트 위치를 읽습니다. Mac의 모든 파일·임의 경로를 빠짐없이 확인했다는 뜻은 아닙니다. 항목이 없을 때는 필터뿐 아니라 제외 규칙과 탐지 범위도 확인하세요.
- 항목을 선택하지 않은 상세 화면의 **Coverage**, **Skipped**, **Issues**에서 읽은 범위·건너뛴 위치·오류를 확인합니다. 일부 스캔이 실패하면 이전 complete 스냅샷이 계속 보일 수 있으므로 **Scan time**, **Latest attempt**도 확인하세요.
- 도구 버전은 설치 메타데이터 관찰입니다. `baseline_match`는 기준과 관찰값 일치, `best_effort`는 기준과 다른 버전에서의 관찰, `unknown`은 버전 확인 불가입니다. 다른 버전에서 파일이 읽혀도 해당 버전의 호환성이 검증된 것은 아닙니다.
- **일부 하네스를 읽지 못했습니다** 또는 **이번 스캔을 완료하지 못했습니다** 경고를 닫아도 오류가 해결되지는 않습니다. 기준 버전·현재 PC 버전과 상세 오류를 확인하세요.
- **SoT 일치**, **SoT에서 변경됨**, **연결 확인 필요**, **확인된 SoT 연결 없음**은 원본과 로컬 관찰의 연결 상태입니다. 파일 발견·파싱·내용 일치는 설치 성공이나 도구 runtime 실행의 증거가 아닙니다.

## 5. beta.6 검색줄의 설치 하네스 제거

> 이 작업은 도구의 실제 파일 또는 설정 항목을 제거합니다. 도구 앱 자체를 uninstall하거나 SoT 컴포넌트를 삭제하는 기능은 아닙니다. 되돌릴 수 없는 작업이므로 영향을 받는 파일을 먼저 직접 백업하세요.

1. **PC 설치 하네스**에서 위치·도구·검색 조건을 좁히고 경로와 원문을 확인합니다.
2. 검색줄 오른쪽의 **설치 하네스 제거**를 누릅니다. 버튼은 **사용 가능한 Local 스냅샷과 현재 검색 결과의 제거 후보가 있을 때** 나타납니다. 제거·결과 확인 중에는 비활성화될 수 있습니다.
3. 선택 모드에서 항목 옆 **제거 선택** 체크박스를 체크합니다. 일반 항목 클릭은 상세 조회일 뿐 제거 선택이 아닙니다. 선택이 0개면 **선택한 0개 제거**는 비활성화됩니다. **선택 취소**로 선택 모드를 종료할 수 있습니다.
4. **선택한 N개 제거**를 누르면 **매번 현재 선택으로 제거 계획을 다시 준비**합니다. 아직 파일을 지우지 않습니다. 한 번에 256개 이하로 선택하세요. 초과하면 계획을 만들지 못합니다.
5. 확인 창에서 제거 예정 이름과 효과를 읽습니다. **Shared config entry 제거**는 공유 설정의 선택 항목 제거이고, **Dedicated harness file 삭제**는 전용 파일 삭제입니다. **부모 폴더 삭제는 0개**입니다. 제거할 수 없는 항목은 변경하지 않습니다.
6. **이 작업이 되돌릴 수 없는 제거임을 확인했습니다.**를 체크해야 최종 **선택한 항목 제거**가 활성화됩니다. **취소**하면 파일을 지우지 않고 선택 상태로 돌아갑니다. 선택을 바꾸거나 다시 진행하려면 **선택한 N개 제거**로 새 계획을 검토하고 다시 최종 승인합니다.
7. 적용 후 자동 재스캔과 확인 상태를 기다립니다. 목록 행을 즉시 숨겨 성공처럼 보이게 하지 않습니다. 새 스냅샷에서 실제 부재를 확인해야 제거 여부를 판단할 수 있습니다.

필터나 페이지를 바꾸면 보이지 않는 선택이 남을 수 있으므로 **선택 수와 최종 확인 창의 전체 제거 목록**을 확인하세요. 제거 계획의 유효기간·스냅샷이 바뀌거나 원본이 계획 이후 수정되면 거부될 수 있습니다. 다시 스캔하고 새 제거 계획을 검토하세요.

제거는 원본 파일을 함께 사용하는 **source group별**로 처리되어 일부만 성공할 수 있으며, 전체 자동 rollback은 없습니다. 실패한 항목이나 결과를 확정하지 못한 항목은 상태 문구를 확인하세요. 재스캔 실패·불완전한 Coverage·미확인 상태에서는 성공 또는 부재를 단정하지 말고 새로고침과 실제 파일 확인부터 진행합니다.

## 6. 가져오기와 편집: SoT와 도구 원본 구분하기

가져오기는 발견한 파일을 HarnessKit 기준 정의로 등록하는 기능입니다. **조회와 달리 연결한 SoT checkout에 쓰기**가 발생합니다.

1. 먼저 SoT를 연결하고 Local 항목의 전체 원문이 준비될 때까지 기다립니다. 상세의 **가져오기 지원 상태**를 확인합니다.
2. 지원 후보에 나타나는 **컴포넌트로 가져오기**를 누릅니다. 명세·본문·지원 문서와 생성 검증 결과를 미리 봅니다.
3. **확인한 컴포넌트 등록**을 누르면 checkout에 canonical 컴포넌트와 registry 변경을 저장하고 출처 연결 기록을 남깁니다. 가져오기만으로 도구 원본을 수정하거나 관리 대상으로 전환하지 않습니다.
4. 가져온 항목을 **Harness Components**에서 선택하고 **가져온 컴포넌트 편집 / 출처 확인**을 엽니다. **Canonical 저장**은 checkout의 본문을 저장합니다. 연결 기록이 없는 기본 항목의 범용 편집 기능은 아닙니다.
5. 편집 내용을 도구 쪽에 반영하려면 **적용 위치: 가져온 원본**을 확인하고 별도로 **Install preview → 이번 적용 승인 → 승인한 preview 적용**을 진행합니다. 원본 위치와 Scope는 가져올 때 연결한 값이며 임의의 다른 경로로 바꾸지 않습니다.

**발견됨 ≠ 가져오기 지원 ≠ 관리 적용 성공 ≠ runtime 실행 성공**입니다. command·workflow, Hermes skill, 일부 도구·Scope 조합과 알 수 없는 필드·의존성 등은 현재 후보 검증에서 차단될 수 있습니다. 버튼이나 오류에 나온 이유를 따르고 원본을 임의로 다른 종류로 바꾸어 우회하지 마세요.

관리 적용 뒤 도구 쪽에서 파일을 수정했다면 외부 수정 보호가 작동할 수 있습니다. 새 Preview의 차이를 보고 도구 쪽 변경을 유지하거나 표시된 원본만 교체하도록 명시적으로 승인합니다. 실패한 가져오기·저장도 무조건 원상 복구됐다고 가정하지 말고 checkout 상태를 확인하세요.

## 7. AI 설명과 개인정보

Local 항목의 **AI 연결 설정**에서 OpenAI-compatible provider의 **Base URL**, **Model**, 필요한 경우 **API key**를 입력하고 **설정 저장**을 누릅니다. 원문이 준비되면 **AI 설명 생성 · 모델명**으로 설명을 요청할 수 있습니다. AI 설정은 기본 조회·검색·설치에 필수가 아닙니다.

- **AI 설명 생성을 직접 누를 때만** 선택한 파일의 **전체 원문**을 설정된 provider로 보냅니다. 화면에 보이는 구간만 보내는 것이 아니며, 저장된 API key가 있으면 요청의 인증 헤더로 함께 전송합니다.
- 스캔·원문 미리보기·가져오기·편집은 원문을 AI provider로 전송하지 않습니다. 전송 전에 비밀·개인정보·조직 자료가 포함됐는지 확인하세요. provider의 사용·보존 정책은 해당 provider의 정책을 따르며 앱이 보장하지 않습니다.
- 원문 한도는 **256 KiB**입니다. 초과하면 일부만 잘라 보내지 않고 요청을 거부합니다. 모델 자체의 입력 한도로도 요청이 실패할 수 있습니다.
- 원격 provider는 **HTTPS**를 사용하세요. 앱은 HTTP도 허용합니다. Loopback이 아닌 HTTP 주소에서는 **API key와 전체 원문이 암호화되지 않은 채 전송될 수 있습니다**. 경고는 표시되지만 요청을 차단하지 않습니다. `http://127.0.0.1:11434/v1` 같은 로컬 loopback HTTP 연결과 구분하세요.
- 이미 저장된 키가 있을 때 API key를 비워 저장하면 기존 키를 유지합니다. 없애려면 **API key 삭제**를 사용합니다.
- AI 설명의 **하는 일**, **언제 사용되는지**, **접근 가능한 기능**, **주의할 점**은 참고용 생성 텍스트입니다. 실제 도구의 로딩·권한·hook 실행을 검증한 결과로 사용하지 마세요.

## 8. 화면 설정과 오픈소스 고지

- **System / Light / Dark**로 컬러 모드를 선택합니다.
- **글자 크기** 메뉴에서 **작게 / 기본 / 크게**를 선택합니다.
- **탐색 패널 열기/닫기**, **상세 패널 열기/닫기**와 패널 사이 구분선으로 공간을 조절합니다. 저장 실패 안내가 나오면 설정이 유지됐다고 가정하지 마세요.
- 앱의 **오픈소스 라이선스**에서 배포 의존성 고지를 확인할 수 있습니다. 저장소에서도 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)를 볼 수 있습니다.

## FAQ / 문제 해결

| 상황 | 확인할 것 |
| --- | --- |
| 앱을 열 수 없음 | [README 설치·보안 승인 안내](../README.md#installation-guide)를 확인합니다. 보안 경고를 임의로 우회하지 않습니다. |
| 폴더 연결 또는 SoT 읽기 실패 | Git 사용 가능 여부, 절대 경로, HarnessKit Git checkout과 registry를 확인합니다. **처리하지 못한 경로 상세**가 있으면 해당 오류를 먼저 확인합니다. |
| 그래프가 보이지 않음 | SoT 연결·읽기 상태와 그래프 렌더링 오류를 확인합니다. 왼쪽 트리와 상세로 구성 조회를 이어갈 수 있습니다. |
| Install preview / 적용 버튼 비활성화 | 컴포넌트·Profile·Target·대상 경로가 선택됐는지, Preview가 준비됐는지, 이번 적용 및 추가 승인을 모두 했는지 확인합니다. 진행 중인 작업이 끝날 때까지 기다립니다. |
| User 또는 특정 Target에서 Preview 실패 | 선택지 노출은 지원 보장이 아닙니다. 해당 컴포넌트·Profile의 지원 범위를 확인하고 지원되는 조합으로 새 Preview를 만듭니다. |
| Local 결과가 없거나 오래됨 | 필터 해제, 발견된 프로젝트·제외 규칙, Coverage·Skipped·Issues, Scan time을 확인하고 다시 스캔합니다. 결과 0개가 도구 부재를 증명하지는 않습니다. |
| 제거 버튼이 없거나 제거 후 행이 남음 | 현재 결과에 제거 후보와 스냅샷이 있는지 확인합니다. 제거 후에는 재스캔·실패·미확인 상태를 확인하고 같은 항목을 곧바로 재삭제하지 않습니다. |
| 가져오기 버튼이 없거나 등록 실패 | SoT 연결, 전체 원문 준비, 후보 종류·Scope의 지원 상태를 확인합니다. 스냅샷·원문이 바뀌었다면 다시 선택하고 미리봅니다. |
| AI 설명 실패 | Base URL·Model·키, 전체 원문 크기와 provider 응답을 확인합니다. 재시도 전에 원격 HTTP 위험도 다시 확인합니다. |

문의할 때는 앱 버전, 대시보드, 작업 순서, 표시된 상태·오류 코드, 관련 snapshot과 destination 결과를 전달하세요. API key, 전체 원문, 개인 경로 등 민감한 정보는 공유 전에 제거합니다.
